# OpenClaw 总体验收与收尾

> 用途：项目整体盘点——阶段清单、对标 nanoclaw 完成度、质量验证、行数盘点、已知边界与后续扩展点。至此五个扩展轴全部完成，项目进入收束。

## 一、项目概览
OpenClaw 是从零手搓的个人 AI 助手平台，对标并复刻 nanoclaw v2.1.54（见 `claw开源项目源码/`），并在其上做多轴自主扩展。核心形态：主机（Node/TS 编排 + SQLite 事实源 + Docker 容器运行时）× 每 Agent 群组隔离容器（Bun agent-runner + provider 抽象 + MCP 工具 + 技能/记忆）× 多渠道投递（Telegram/Discord/Slack/飞书/钉钉/企微/邮件/Webhook/CLI）× CLI/Web 双管理面。

**承重不变量（全程守住）**：双 DB 会话架构（inbound 主机写/outbound 容器写，open-write-close，单写者）；帧不携带身份（调用者带外填充）；guard fail-closed（grant 只满足 hold 永不松动 deny）；fs 沙箱 safeJoin；秘密不进容器 env；迁移 name 去重 + FK 安全协议。

## 三、对标 nanoclaw 完成度总览
- **已复刻**：双 DB 会话、帧协议与带外身份、guard/grant 语义、迁移 FK 协议、容器编排、CLI dispatch、审批闭环、渠道透传适配器、技能即 Markdown。
- **简化**：审批选项为纯字符串（基线为 label/value 分离）；RAG 为 BM25-lite（基线无，属自研简化）；静态控制台为遗留 fallback。
- **自主扩展（基线无）**：评估/观测体系、React 前端、9 渠道全量、容器技能库、i18n 三语、安装向导 nc: 指令引擎。

## 四、质量与验证
- **测试**：host 290 用例（36 文件）/ frontend 15（5 文件）/ container 24（bun），全绿；测试全 Mock，无真调 LLM/Docker/网络。
- **静态**：host + frontend `tsc --noEmit` 全绿；`eslint` 全绿。
- **检查员**：每阶段经 se-inspector（架构/TS/安全/测试）与 ai-inspector（AI 链路/上下文/评估）审查，P0/P1 均修复并留档于各 `phase-N` 文档「所遇问题与修复方案」节。

## 六、已知边界与后续扩展点（留档，非缺陷）
1. **每群组 locale**：渠道/审批当前用宿主 `OC_LOCALE`；per-group locale 注入系统提示为扩展点（phase-14）。
2. **评估语料多语化**：检索/判分已支持 zh/en/ja（tokenize 假名 + 多语拒答正则 + LlmJudge 拒答分支），但种子语料与改写前缀仍中文为主，seed-en/seed-ja 待补（phase-14 ai-inspector P1-2）。
3. **RAG 向量后端**：BM25-lite 现状，pgvector/embedding（BGE-M3 多语）预留未接（phase-12）。
4. **React 前端供给管线**：目前仅 vite dev，无 build→static 接入主机 `/`（主机 `/` 仍供静态控制台）（phase-14 se-inspector P2-10）。
5. **审批选项 label/value 分离**：接入渠道审批按钮前需先分离，避免本地化标签成为决策值（phase-14 ai-inspector P2-5）。
6. **容器内 ncl 传输**：落地后 dispatch 本地化错误将以工具结果进入 LLM 上下文，建议返回稳定 code + locale 无关文本（phase-14 ai-inspector P2-9）。
